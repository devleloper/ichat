# iChat Client

Flutter-клиент для обмена сообщениями в реальном времени, написанный с упором на чистую архитектуру, надежную работу с WebSocket и отзывчивый iOS-подобный UI.

## Архитектура: Clean Architecture

Проект строго разделен на 3 классических слоя (Data, Domain, Presentation). Никакой бизнес-логики или работы с сетью внутри виджетов.

1. **Data Layer (Слой данных):**
   - **REST API** реализован через `Dio`.
   - **WebSocket** вынесен в отдельный, полностью изолированный класс `WebSocketClient` (на базе `web_socket_channel`). Он берет на себя всю низкоуровневую работу: поддержание соединения, пинги, автоматический реконнект с экспоненциальной задержкой (Exponential Backoff) и парсинг JSON.
   - **Репозитории** (`AuthRepository`, `ChatRepository`) абстрагируют источники данных и предоставляют интерфейсы для Domain-слоя.

2. **Domain Layer (Слой бизнес-логики):**
   - Содержит чистые сущности (`User`, `Room`, `Message`), не привязанные к конкретным библиотекам.
   - Описаны UseCase'ы (например, `SendMessageUseCase`, `GetMessagesUseCase`), которые оркестрируют вызовы к репозиториям.

3. **Presentation Layer (Слой отображения):**
   - Разбит по фичам (auth, chat_list, chat_room).
   - Внутри каждой фичи используется строгий BLoC для управления состоянием.

## Управление состоянием: BLoC

В качестве State Manager выбран **BLoC (`flutter_bloc`)**. 
Выбор обоснован тем, что мессенджеры — это приложения с огромным количеством асинхронных событий (отправка сообщения, входящие вебсокет-события, изменение статуса "печатает", обрывы сети). BLoC идеально ложится на такую архитектуру:
- События сети (REST/WS) маппятся в `ChatRoomEvent`.
- Состояние чата (`ChatRoomState`) всегда иммутабельно (используется `freezed` для глубокого копирования состояний).
- Это позволяет легко реализовывать Optimistic UI и сливать воедино локальные отправленные сообщения и данные, приходящие из WebSocket-стрима, избегая гонок данных (race conditions).

## Realtime и Optimistic UI

### 1. Бесшовный Optimistic UI
При отправке сообщения мы не ждем ответа сервера:
- Сообщению мгновенно присваивается локальный `client_message_id` (UUID v4) и статус `MessageStatus.sending`.
- Блок немедленно эмиттит новое состояние, и сообщение появляется в UI.
- Когда по WebSocket прилетает событие `message.created`, мы ищем сообщение по `client_message_id` и бесшовно обновляем его статус на `sent` (и проставляем реальный ID из БД). Никакого дублирования или дерганья списков не происходит.

### 2. Умная обработка "Собеседник печатает"
- При наборе текста в TextField отправляется WS-событие `typing`.
- При получении `typing` от собеседника, BLoC взводит флаг `isOtherUserTyping` и запускает таймер. Если новых событий `typing` нет в течение 3 секунд, состояние сбрасывается.

### 3. Автоматическое восстановление (Reconnect)
При обрыве связи:
- `WebSocketClient` пытается переподключиться в фоне.
- BLoC реагирует на переподключение: как только соединение восстановлено, он запрашивает последние сообщения через REST API (`GET /api/rooms/.../messages`). 
- Полученные данные мерджатся с текущим списком по ID. Это гарантирует, что история не потеряется (если сообщения пришли во время дисконнекта) и не задублируется.

## Нативный iOS-like UX / UI 

Огромное внимание было уделено визуальной части и микро-анимациям, чтобы приложение чувствовалось "дорогим" и неотличимым от нативного iMessage:

1. **Squircle-бабблы и хвостики:** 
   Бабблы сообщений отрисованы вручную через `CustomClipper` (для плавного закругления углов) и `CustomPainter` (для отрисовки классических хвостиков направленных к краям экрана). 

2. **Анимация вылетающего текста (Flying Text):**
   При нажатии на "Отправить", текст не просто исчезает из поля ввода. Создается `OverlayEntry`, который плавно переносит точную копию текста из `TextField` вверх, в список сообщений, постепенно растворяя его с использованием линейной кривой прозрачности (opacity) и трансформаций (translate), чтобы текст таял строго внутри границ панели ввода.

3. **Абсолютно плавный сдвиг истории сообщений:**
   Новые сообщения появляются с использованием `SizeTransition` (с якорем сверху — `Alignment.topCenter`). Благодаря этому новые сообщения плавно "раздвигают" пространство, мягко выталкивая старую историю вверх без использования `SlideTransition`, что полностью исключает наложения (overlays) и дерганье (scroll jerks).

4. **Менеджмент отступов (Padding Fix):**
   Чтобы избежать резких скачков списка при группировке сообщений (когда исчезает хвостик у предыдущего сообщения в группе), логика отступов была перевернута: теперь за отступ между сообщениями отвечает *верхний* паддинг нового сообщения (на основе флага `isFirstInGroup`), а не нижний паддинг старого. Это сделало анимацию появления железобетонно стабильной.

5. **Гиперотзывчивые кнопки (Hyper-Responsive BounceButton):**
   В Flutter `GestureDetector` внутри списков (`ScrollView`) искусственно задерживает срабатывание `onTapDown` на ~150мс, ожидая, не скроллит ли пользователь. Из-за этого кнопки кажутся тугими. Мы обошли это, используя низкоуровневый `Listener` (`PointerDownEvent`) для визуальной анимации сжатия (bounce), оставив логический клик на `GestureDetector`. В результате кнопки реагируют на легчайшее прикосновение мгновенно.

6. **Glassmorphism и Large Titles:**
   На экране списка чатов внедрен нативный `CupertinoSliverNavigationBar`. В стартовом положении заголовок крупный и прибит к левому краю, а при скролле он плавно уменьшается, уходит в центр и включает идеальный "яблочный" блюр-эффект (BackdropFilter) с тонкой окантовкой. Тот же эффект матового стекла применен к AppBar'у и панели ввода в самом чате.
